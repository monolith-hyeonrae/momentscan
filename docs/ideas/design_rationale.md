# 설계 결정 기록 — 왜 이렇게 푸는가 / 왜 이렇게 *안* 푸는가

> 목적: *흘러온 맥락*과 *시도했다 실패한 길*을 보존해, 신규 개발에서 같은 질문에 같은 실수를 반복하지 않게.
> "왜 이 문제를 이렇게 안 풀어요?"가 다시 나올 때 → 여기를 보면 됨.
> (원리: `selection_insights.md` · 설계: `architecture_design.md`, `architecture_worldmodel.md`)

## 0. 한 줄 요약

이 문제는 **선택(상대)**이지 **분류(절대)**가 아니고, 구조는 **데이터에서 발견**하지 **외부에서 강요**하지 않는다. 의심되면 §2를 보라.

## 1. 흘러온 맥락 (the journey)

문제는 단순하게 시작했다: 비디오 스트림에서 타겟 인물 p에 대해 Likeness·Portrait·Highlight를 골라내는 것. 처음엔 자연스럽게 *감독학습과 큐레이션* 접근들을 시도했다 — 좋은 프레임을 분류하고, 좋은 세트의 분포를 닮게 뽑고, 포즈·표정 카테고리로 모으고, 긍정/부정 방향을 배우고. 그런데 넷 다 *같은 종류의 벽*에 부딪혔다(§2).

그래서 쌓아온 해법 전제를 *전부 내려놓고*, "확실한 것"부터 다시 쌓았다. 거기서 핵심 전환이 나왔다 — **curation-free 상대 선택이 *옳은* 틀이라는 것.** 우리 조직이 정교한 큐레이션을 못 해서가 아니라, 문제의 구조 자체(연속적이고, 상대적이고, 발견되는)가 *원리적으로* 큐레이트 불가능하기 때문이다. 큐레이션을 요구하는 접근은 자원이 무한해도 같은 미스매치로 깨진다.

다음으로 각 출력의 *목적*을 못 박았다 — 목적이 설계를 제약하니까. Highlight는 *추억*(나중에 한 장으로 그날 전체가 되살아나는 것), Portrait는 *PFP 같은 컬렉션*(개성 넘치되 규칙·균형 있는), Likeness는 *아바타*(외형 불변량 추출). 그러자 통합이 드러났다: **세 출력은 사실 한 substrate — per-person baseline — 의 세 면**이다. Likeness는 그 불변량을 추출하고, Portrait는 거기서 특징적으로 벗어난 깨끗한 프레임을 고르고, Highlight는 크게 벗어난 순간을 고른다.

마지막으로 *어떻게*를 정했다: **predictive video world-model**, 거기서 salience = surprise(예측 오차). 모델의 *예측*이 Likeness(안정된 self), *예측 오차*가 Highlight(놀라운 순간)다. (상세는 `architecture_worldmodel.md`.)

## 2. 왜 이렇게 *안* 푸는가 — 재발 방지 FAQ

각 항목 = *누군가 다시 물을 질문* → *시도했고, 왜 실패했고, 교훈*.

### Q1. "그냥 좋은/나쁜 프레임으로 *분류*하면 안 돼요?"
시도함 → 실패.
- 거의 *똑같은* 프레임이 한쪽은 채택, 한쪽은 기각된다 → 프레임 하나로 가르는 함수는 *모순*(같은 입력, 다른 라벨).
- 모든 촬영 시점을 정의할 수 없어 데이터 늘수록 경계가 모호, 극단적 불균형(채택은 희소).
- 상대 우열 레이블(A vs B)로 바꿔도 *작은 격차*에선 판단이 흔들린다(노이즈 바닥) — 이번에 뽑힌 게 다음엔 안 뽑힘.

**교훈:** 라벨은 *프레임*이 아니라 *비교*에 산다. → 단일 최선 아닌 *top-set*, *확신 비교*로만, 애매한 중간은 *기권*.

### Q2. "확실한 포트레이트 세트를 만들고, 그 *밀도*로 닮은 프레임을 뽑으면?"
시도함 → 실패.
- density는 *전형성/빈도*를 잴 뿐 *품질*이 아니다 → "좋다"가 "내 세트에서 흔하다"가 되어 *평범한 장면으로 수렴*.
- 최고는 정의상 *드물어*(저밀도 꼬리) → density가 기각한다.
- 수집 비율(밸런스)에 결과가 휘둘린다.

**교훈:** 좋음은 *영역(region)*이 아니라 *방향(direction)*이다.

### Q3. "포즈/표정 *카테고리(버킷)*를 만들어 앵커로 모으면?"
시도함 → 데이터 적을 땐 되다가, 많아지면 실패.
- 실험실 카테고리의 깔끔함은 *"기준→사진"(생성)의 인공물*이다. 현실은 *"사진→기준"(서술)*이라 연속이고 in-between투성이 → 버킷 경계가 흐려져 막 섞인다.
- 카테고리(7감정·포즈클래스)는 natural kind가 아니라 *라벨링 프로토콜의 편의*.

**교훈:** 강요할 칸막이가 아니라 *데이터에서 발견되는 연속 구조*. 애매한 중간은 기권.

### Q4. "긍정/부정 극단을 배워 *단일 방향*으로 (positive 가깝게, negative 멀게) 뽑으면?"
시도함 → 실패.
- 포트레이트 품질은 여러 요인의 *논리곱*(조명 ∧ 표정 ∧ 포즈 ∧ 선명 ∧ 비가려짐).
- 부정이 *이질적*(각자 다른 축에서 나쁨) → 단일 "away" 방향이 없다.
- 결합이 합이 아니라 *최솟값(min)*; binary 라벨이 *어느 요인 때문인지* 안 알려준다(credit assignment 부재 = "왜 기각됐는지 모름").

**교훈:** *요인별 분해* — 대부분 객관(선명·가려짐·조명·포즈), 어려운 건 *표정 한 축*으로 격리.

### Q5. "그냥 *감정 인식기* 출력을 쓰면?"
안 됨.
- 선택에 필요한 건 "*무슨* 감정"이 아니라 "*얼마나* baseline에서 벗어났나"(magnitude). 감정 인식기는 *틀린 질문*에 답한다.
- 감정 카테고리 = Q3의 함정 재현. FER 임베딩도 *가짜 카테고리로 collapse*돼 있다.

**교훈:** 표정 신호 = *magnitude*(자기 baseline 대비 거리), not 카테고리. *일반* 표현 사용(감정-과제 학습 ✗).

### Q6. "큐레이션을 더 잘하면(자원이 많으면) 되지 않아요?"
안 됨 — *원리적으로*.
- 문제 구조(연속·상대·발견된)는 큐레이트가 불가능하다. 자원이 무한한 조직도 같은 구조적 미스매치로 깨진다.

**교훈:** curation-free는 타협이 아니라 *옳은* 제약. 신호는 *인스턴스 내부-상대*거나 *원본 데이터 고유*, 절대 *사람이 큐레이트하지 않는다*.

### Q7. "큰 VLM에 '이거 좋은 하이라이트야?' 물어보면 되잖아요?"
부분적으로만 — naive하게는 안 됨.
- 프레임을 *절대* 점수 매기면 Q1 위반(상대 문제에 절대 잣대) + 흔한-것 편향(mode-collapse) + 종일 스트림 real-time 불가.
- 올바른 사용: VLM을 *judge*로 — *confident pairwise 비교를 생성*(사람 큐레이션 0)하고, *내부 상대*로만 쓰고, 빠른 ranker로 distill.

**교훈:** VLM은 *상대 비교 생성기*지 절대 점수기가 아니다.

## 3. 공통 뿌리 (모든 실패의 한 원인)

위 전부 = **이산·절대·사전정의·외부큐레이트 구조를 / 연속·상대·발견된 현실에 강요**한 것.

→ 한 문장 진단: *"좋음/중요함"을 외부에서 가르치려 했다. 사실 그건 데이터 안에 자기-상대 구조로 이미 있다 — 좋은 표현으로 읽기만 하면 된다.*

## 4. 새 사람에게 (onboarding 한 단락)

이 문제를 처음 받으면 *분류기*나 *카테고리 데이터셋*이나 *감정 인식기*가 당겨질 거다. 위 §2가 *왜 그 길들이 막다른 길인지* 보여준다. 핵심만: 이건 *분류*가 아니라 *상대 선택*, *외부 강요*가 아니라 *내부 발견*. 새 아이디어가 떠오르면 — 그게 §2의 어느 항목과 *같은 가정*을 깔고 있는지 먼저 확인하라.
