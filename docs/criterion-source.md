# momentscan — 판단 기준의 출처 (개념 렌즈)

> products.md가 각 제품의 *정의*라면, 이 문서는 세 제품을 **하나의 그림으로 묶는 해석 렌즈**다.
> momentscan의 개념적 복잡성을 낮추기 위한 것. 억지 분류가 아니라, 이미 지어진
> 세 제품(likeness / portrait / highlight)에서 *공통 구조*를 추출한 것이다.

## 한 문장

**세 제품은 같은 "기준 매칭" 기계다. 바뀌는 것은 판단 기준이 *어디서 오느냐*(출처)이고,
그 출처가 기준이 사는 *공간*(=매칭 방식)을 결정한다.**

```
기준의 출처 :  피사체  ─────────▶  저작자  ─────────▶  맥락
제품        :  likeness           portrait            highlight
기준의 공간 :  생체 임베딩         기하(blendshape)     의미/언어
매칭        :  ArcFace 근접        query 근접          VLM/CLIP 유사도
제어        :  불가(사실)          저작자(쿼리·계절)    맥락/도메인(기대 서술)
```

세 제품 모두 본질은 "**어떤 기준에 얼마나 가까운가**"를 재는 것이다. 이것이 "코어 스위치":
세 제품은 서로 다른 기계가 아니라, **같은 기계가 서로 다른 기준을 코어로 승격**한 것이다.

## likeness — 기준이 피사체에게 있다

- **질문**: 누구인가?  정체성은 **사실**이다(객관·불변).
- **역할**: 피사체는 그냥 **존재(Be)**한다. 관측자는 확인만 한다.
- **기준의 공간**: **생체 임베딩**(ArcFace). 정체성은 말로 서술할 수 없다 — 그냥 매칭한다.
- **제어**: 불가. 정체성은 저작하거나 맥락이 바꿀 수 있는 것이 아니다.
- **불변축**: 표정·시간에 대해 **INVARIANT**(방문-불변). likeness는 정면 코어로 *수렴*한다.

## portrait — 기준이 저작자(사진사)에게 있다

- **질문**: 이 사람을 **어떤 순간에** 담을까.
- **역할**: 피사체는 내면의 변화와 외부의 영향으로 **끊임없이 변하는 Be**다. 사진사는
  그 **변화를 살펴 최적의 순간을 포착**한다. 피사체 입장에선 그냥 존재이지만,
  촬영자는 그 변화 위에서 고른다.
- **"최적"의 성격**: 일반해(누구나 좋다 할 순간)도 있지만, **주관적이고 미션마다 다르다.**
  여름 PFP와 겨울 PFP가 다르고, 사진사마다 해석이 다르다. → 그래서 기준(query)이
  **제어 가능**하고 계절·사용자별로 바뀐다. 저작자가 곧 기준이다.
- **기준의 공간**: **기하 공간**(정준 blendshape 타깃). 표정 상태는 정적인 얼굴 배열이므로
  기하 근접으로 정확히 잰다. → 이것이 구현된 **query-proximity**(portrait-render-query).
- **제어**: 저작자가 쿼리로. 다중모달(param / image / text)로 저작 가능.

## highlight — 기준이 맥락(어트랙션)에서 온다

- **질문**: 이 맥락에서 **기대된 것을 해냈는가**.
- **역할**: 맥락(어트랙션)이 **기대를 전제로 규정**한다. 축구의 하이라이트(골)와 레이싱의
  하이라이트(추월)가 다르듯, 어트랙션마다 하이라이트의 정의가 다르다. 피사체의 돌발
  상황도 하이라이트가 되지만, 진짜는 **그 경기에서 기대된 무언가의 달성**이다.
- **기준의 공간**: **의미/언어 공간.** 기대는 정적 얼굴 배열이 아니라 **동적 사건**이고,
  사건은 언어가 가장 잘 담는다. → 어트랙션별 기대를 **텍스트로 저작** → 순간을
  **VLM/CLIP 의미 유사도**로 대조. 조건부: **P(highlight | attraction · course · segment · person)**.
- **제어**: 맥락·도메인이 (어트랙션별 기대 서술).
- **주의(레거시 교훈)**: 초기에 CLIP으로 *표정 카테고리*를 매칭했으나 성능 미달로 배제.
  그 실패는 CLIP을 **미세 표정 분류기**로 쓴 것(CLIP의 약점) + **얼굴 크롭**(사건이
  프레임 밖). 현재 방향은 **사건-수준 서술 + 더 넓은 라이더 크롭**(몸짓·장면이 보이는)
  으로, CLIP/VLM의 *강점*(홀리스틱 장면·사건)을 친다 — 다른 실험이다.

## 대칭과 함의

- **매칭 양식이 기준 출처를 따라간다**: 생체(사실) → 기하(저작) → 언어(맥락). portrait와
  highlight는 둘 다 "query-proximity"지만, **기준의 본성(정적 상태 vs 동적 사건)이
  공간을 가른다.** portrait-render-query의 다중모달에서 *text*가 바로 highlight의 자리다.
- **제어 gradient**: likeness 불가 · portrait 저작자가 · highlight 맥락/도메인이.
- **WHICH / WHY**: 모든 제품은 자기 기준 위로 *reduce*해 대표(rep)/구간(segment)을 뽑는다
  (WHICH = 선택 연산자). 왜 그렇게 됐는지는 gate_trace·provenance·인스펙터가 축을
  가로질러 읽는다 (WHY = 관측 레이어).

## 정직한 경계

- 5W1H(WHO/WHAT/WHEN/WHERE/HOW)는 **렌즈이지 감옥이 아니다.** 모든 셀을 억지로
  채우지 않는다. 위의 "기준 출처" 프레임이 덜 강제적이고 momentscan을 더 잘 설명한다.
- 일부 제품은 축이 섞인다(highlight의 WHEN×WHICH 결합 등). 이를 하나의 균일한
  "레시피 엔진"으로 통합하는 것은 유혹적이나 **큰 통합 리팩토링**이다 — 축 추상이
  누수 없이 버티는지 검증(한 축을 substrate로 승격하는 파일럿)이 선행. 지금은 이
  프레임을 **서술/렌즈**로 유지한다.
