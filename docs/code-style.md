# momentscan 코드 스타일 — 하우스 규칙 (2026-07-15 초안)

> 목적: 사람과 모델이 함께 만지는 연구+서비스 겸용 코드의 **일관된 대원칙**.
> 출처 = 이 레포에서 이미 관측되는 관례의 성문화 + user 확정 원칙(2026-07-15).
> 적용 = **신규·수정 코드부터** — 소급 전면 리포맷 금지(diff 오염, R9 원칙).
> enforcement = ruff 검사(R9, baseline 후 신규 위반만) + 이 문서 + 리뷰.
> 새 코드가 이 문서와 어긋나면: 코드를 고치거나, 문서를 고치거나 — 침묵 금지.

## 1. 함수/메서드

- **한 함수 = 한 책임.** 이름이 책임을 서술한다(동사구). 이름에 "그리고"가
  필요해지면 분리 신호.
- **길어지면 의미 단위로 추출한다.** 하드 리밋보다 판단 기준: 한 화면(~40줄)을
  넘거나 빈 줄 없이 30줄이 흐르면, 의미 단락을 `_동사_명사` 사설 함수로 추출.
  추출은 재사용이 아니라 **가독성**을 위한 것 — 한 번만 불려도 이름이 설명력을
  가지면 정당하다.
- **조건 분기는 early-return으로 중첩을 줄인다** — 해피 패스가 왼쪽 끝에서
  흐르게. `else` 뒤에 본론이 오는 함수는 뒤집기 신호.
- **반복되는 추출/판정 로직은 의도가 드러나는 이름의 헬퍼로 분리한다** —
  `_is_frontal(row)`, `_worn_frac(frames)`처럼 판정의 "무엇"이 이름이 되게.
  같은 술어/추출식이 두 번째로 복붙되는 순간이 분리 시점이다(§2의 매직 값
  규칙과 짝: 값은 상수로, 식은 이름 있는 헬퍼로).
- 인자 4개 초과는 재고; 불리언 위치 인자 금지(키워드로).
- 공개 함수는 타입힌트. 반환이 복합이면 형태를 독스트링 한 줄로.

## 2. 매직 값 — 이 레포의 1급 규칙

- **매직 넘버/스트링은 명명된 상수로 추출한다.** 모듈 상단, UPPER_SNAKE,
  단위 접미(`_S`, `_MS`, `_DEG`, `_PX`) 필수.
- **연구/정책 임계값은 3요소 의무: 이름 + 단위 + 근거 주석** — 어느 실측·
  코퍼스·사고에서 온 값인지. (좋은 전례: `TOKEN_MARGIN_S = 60  # 만료 레이스
  방지`, `FRAG_TAU = 0.40  # 코퍼스 99쌍 음성대조 max 0.32의 여백`.)
- 정책성 상수(시설/기구 바뀌면 달라질 값)는 **C9 preset 지향** — 코드 산개를
  발견하면 R8 인벤토리(docs/preset-inventory.md)에 등록부터.
- 문자열 계약(스키마 ID·모듈 경로·토픽명)은 **한 곳에 선언하고 참조** —
  같은 리터럴의 복붙 산개 금지 (전례: STAGE_MODULE, `momentscan.likeness/v1`).

## 3. 예외 처리와 열화 — 정직하게

> **머리 원칙 (user, 2026-07-15): 어설프게 돌아갈 바에는 기준에 미달하는 순간
> 확실히 죽이고, 어디서 어떤 문제로 죽었는지 명확하게 가시화한다.**
> 최악은 crash가 아니라 오염된 상태로 계속 도는 것 — 증상은 위반 지점에서
> 멀리 떨어진 곳에서 나타나고, 그때는 원인을 역추적해야 한다(freshness
> 무증상 실명 D1이 이 레포의 실사례). fail-fast의 죽음 단위는 문맥이 정한다:
> 라이브러리/스테이지 코드 = 즉시 전파, 장기 서비스 = **잡(job)이 죽음의
> 단위** — 한 잡은 stage+error를 지참하고 시끄럽게 죽고, 프로세스는 산다
> (경계 캐치는 fail-fast의 예외가 아니라 폭발 반경의 설계다).

- **죽을 때는 지참물과 함께**: assert/raise 메시지에 위반한 실제 값·기대
  기준·문맥(clip_id 등)을 싣는다. `"invalid state"`는 금지 —
  `f"STAGE_MODULE에 해석 불가 모듈 경로: {_dangling}"`처럼 메시지만 보고
  원인 지점으로 갈 수 있어야 한다.
- **try 범위는 좁게**: 실패할 수 있는 문장만 감싼다. 함수 전체를 try로 덮는
  것 금지 — 어느 줄이 실패 가능한지가 코드에서 읽혀야 한다.
- **잡을 예외를 특정한다.** `except Exception` 광역 캐치는 경계(스테이지
  러너·서비스 워커 루프·콜백·heartbeat)에서만 — 반드시 기록과 함께.
  bare `except:`는 어디서도 금지(KeyboardInterrupt까지 삼킨다).
- **복구 계획이 없으면 잡지 않는다** — 전파가 기본값. 잡는 정당한 이유는
  둘뿐: ①경계에서 기록하고 정직하게 열화 ②문맥을 붙여 재-raise.
- **열화 경로는 침묵 금지**: 폴백/빈 반환으로 진행할 땐 `log.warning`에
  사유(`reason`)를 싣는다. "품질 떨어진 산출물이 정상처럼 나오는" 경로가
  최악(L5).
- `ImportError`는 선택-의존 경계의 정당한 skip 사유(파이프라인 "dep missing"
  패턴, boto3 lazy) — 그 외 문맥에서 잡지 않는다.
- 불가능 시나리오용 방어 코드 금지 — 필요한 실패는 크게 실패시킨다.

### 3a. assert의 자리 — "파이썬에서 assert 잘 안 쓰나?"에 대한 답

안 쓰는 게 아니라 **용도가 좁게 정해져 있다.** `python -O` 최적화 플래그가
assert 문을 통째로 제거하므로, assert에 실린 검사는 "없어도 돌아가야 하는"
것이어야 한다:

- **assert = 프로그래머 불변식·선언 정합 전용.** 이 레포의 확립 패턴 =
  import-time 선언 드리프트 가드(analyzers ⇄ RUNNERS ⇄ STAGE_MODULE,
  PRODUCTS 정합, tier 유효성) — 선언이 어긋나면 프로세스가 뜨기도 전에
  죽는 것이 목적이고, 같은 검사가 `momentscan verify registry`(CLI)에도
  있어 -O 환경에서도 안전망이 이중이다.
- **외부 입력·런타임 데이터 검증에 assert 금지** — 그건 `raise ValueError(...)`
  같은 정직한 예외로. 계약 경계 검증은 msgspec(R6)의 몫.
- 테스트 코드에서는 assert가 표준(pytest가 assert 재작성으로 동작).

## 4. 로깅과 출력

- 로그 = 구조화: `log.info("계.층.이벤트", extra={...})` — 메시지는 점-구분
  이벤트명, 데이터는 전부 extra(Loki 계약). f-string으로 데이터를 메시지에
  녹이지 않는다.
- `print`는 CLI 표면(사람 대면 출력) 전용. 라이브러리 모듈에서 print 금지.

## 5. 모듈

- **모듈 독스트링 = 계약과 왜.** 무엇을 소유하는지, 어떤 원칙/사고/결정에서
  왔는지(날짜·앵커 환영). 긴 독스트링은 이 레포의 미덕이다.
- 주석은 **코드가 말할 수 없는 제약·근거만** — 다음 줄이 뭘 하는지 반복 금지.
- 모듈 내부 순서: 독스트링 → import(표준/서드파티/내부 3그룹) → 상수 →
  공개 API → 사설 헬퍼. 큰 구획엔 배너 주석(`# ── 이름 ──…`) — 기존 관례.
- 내부 임포트는 **4결 순서(infra→perception→products→기타)** — A″ 그룹을 임포트
  블록에서도 읽히게(의존 방향 = 시공→관측→제품). ruff isort("I")가 강제.
- lazy import는 **경계에서만**: CLI 핸들러, 무거운 백엔드(GPU·모델),
  선택 의존(boto3). 일반 모듈 내부는 상단 import.

## 6. 수직 공백 — "빈 줄 = 문단 경계" (2026-07-16 개정: user "너무 빡빡해")

- **세로 공간을 아끼지 않는다 — 화면은 싸고 독해는 비싸다.**
- 최상위 함수/클래스 사이 2줄, 클래스 내 메서드 사이 1줄(PEP8).
- 함수 안 의미 단락 사이 빈 줄 = **의무** (빈 줄 없이 이어 붙이지 않는다).
- **주석 문단 앞에는 빈 줄 의무** — 주석은 다음 블록의 제목이지 이전 코드의
  꼬리가 아니다.
- guard 절·조기 return 뒤 빈 줄. 함수의 리듬: 준비(읽기)/본론(계산)/마무리
  (기록·반환) 사이 빈 줄.
- **만진 함수는 숨 쉬게 하고 나온다** — 수정하러 들어간 함수는 그 스코프에서
  단락 정리 허용(boy-scout). 함수 밖 전면 리포맷은 여전히 금지.
- 연속 빈 줄 2개 이상을 함수 안에 두지 않는다.

## 7. 네이밍

- 파일/패키지 = **책임명** — `utils`·`common`·`misc`·`helpers` 금지(잡동사니
  서랍 방지 원칙). 통합이 필요하면 책임으로 명명한 홈을 만든다.
- 사설은 `_접두`. 재수출 아니면 `__init__.py`는 얇게.
- 개명된 개념의 잔재(구명칭 주석·독스트링)는 발견 즉시 청소 대상 — 선언과
  주석이 거짓말하면 "선언=데이터" 원칙이 침식된다(D6).

## 8. 검증 동반

- 비자명 변경은 커밋 전 verify(registry/api/replay 또는 특성화) — CLAUDE.md
  하드 룰. 수치 코드 접힘은 tolerance-replay, 저장/직렬화 접힘은
  byte-identical이 기준.
- 계약(C·p981.if.*) 접점 코드는 additive만 무버전 — 의미/형태 변경은
  버전 승격+소비자 동시.
