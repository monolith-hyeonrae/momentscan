## 1. 계약 맥락 — B1 진화 (우리=값 공급 · 디자인팀=몰프 저작)

MomentScan(scan)은 비디오에서 관측한 얼굴 개성을 **face_recipe** 로 추출한다.
recipe 는 측정 **37축(Cat G, 얼굴 기하)** 을 담지만, 현재 디자이너 리그
(`body+basic_260527.blend`)의 **shape key 는 13개**뿐이라 그 13키가 소비하는 축은
**19개**에 그친다. 나머지 **18축이 리그에 표현되지 않는다**.

> **user 관찰 (race981 A/B 판정 중)**: "개인 특성(얼굴형·눈 쳐짐·눈 간격)이 두드러지지
> 않아 재미없다 — 쉐입키의 한계인가?"

실측 결과 **얼굴형 계열 5축이 전멸**(윤곽 몰프는 `Chin_Length` 하나뿐), 눈 개방형태
4축·코 3축도 미표현. 얼굴 실루엣과 이목구비 비례가 3D 캐릭터에 안 실리니 개인차가
약할 수밖에 없다.

**계약 진화(B1)의 방향**:

| 주체 | 책임 |
|---|---|
| **scan (우리)** | 미표현 축의 값을 **shape key 값 [0,1]** 로 공급한다 (이 문서 §3 표). |
| **디자인팀** | 각 제안 키에 대응하는 **리그 몰프(변위)를 저작**한다. 키당 변위 폭·방향의 조형은 리그 저작 영역(우리는 [0,1] 정규화 값만 전달, 물리 변위 크기는 저작자 재량). |

- **13키는 불변**: 현 `body+basic_260527.blend` 의 shape key 와 1:1 대응하며 이 제안이
  건드리지 않는다. 이미 저작된 표면 그대로다.
- **제안 12키는 신설 대상**: blend 에 아직 없다. scan 은 이미 값을 계산해 공급할 수 있고
  (렌더 파이프가 미매칭 키로 **자백**한다 — 아래 §4), 디자인팀이 몰프를 만들면 즉시
  프리뷰에 반영된다.

## 2. gain 정책 (L-B ③)

프리뷰 shape key 값은 neutral(=0)에서의 편차에 **gain 배율**을 곱해 과장할 수 있다
(clamp [0,1]). 개인차가 좁아 육안 판정이 어렵다는 L-B ③ user 판정에 따라:

- **기본 gain = ×2.2** (`viz-recipe` 기본값, 코드 상수 `DEFAULT_GAIN`).
  근거: ×1.0(항등)은 개인차가 미약, ×2.2 채택 — A/B 몽타주 판정 재료.
- `viz-recipe --ab gain` = ×1.0 vs ×2.2 나란히 비교(판정용).
- 특성화 골든은 gain=1.0(수학적 항등)에서 raw 투영을 봉인 — gain 은 **렌더-표시 노브**지
  투영 산식이 아니다. 정책 기본(2.2) ≠ 순수 함수 기본(1.0).

**주의**: gain 은 표현을 과장할 뿐 미표현 축을 만들지 못한다. 얼굴형 개인차는 gain 이
아니라 **§3 확장 키**로만 해소된다(두 처방은 별개 축).

## 5. 렌더 파이프 동작 (자백 메커니즘)

`viz-recipe` 렌더 경로는 제안 키까지 값을 계산해 blender payload 에 싣는다. blender 는
**blend 에 존재하는 키(현 13키)만 적용**하고, 없는 키(제안 12키)는 조용히 넘기지 않고
로그로 **자백**한다:

```
rendered <png> (applied=13/13, hair=—)
  WARNING unmatched shape keys: ['Face_Aspect', 'Jaw_Width', ... ]
```

이 자백 목록이 디자인팀 저작 대기열이다 — 몰프를 만든 키는 자백에서 빠지고 렌더에
반영된다. 몽타주 상단 제목도 `rig 13/13 mapped + 12 proposed keys [ledger 10]` 로
현 두-계층 상태를 자기-문서화한다.

## 6. 남긴 판단 (디자인팀 확인 요망)

- **명명 접두 불일치**: 제안 눈썹 키를 `Eyebrow_Arch`·`Eyebrow_Eye_Distance` 로 두었으나,
  현존 눈썹 키 4개는 `Eyebrow_` 접두를 쓴다(`Eyebrow_Thickness` 등). 저작 시 리그
  일관성을 위해 `Eyebrow_Arch`·`Eyebrow_*` 로 조화시킬지는 디자인팀 재량(의미는
  source axis·한글 열로 명확). scan 코드 상수(`PROPOSED_SHAPE_KEY_MAP`)만 함께 갱신하면
  된다.
- **키당 변위 폭**: [0,1] 정규화 값의 물리 변위 매핑(예 Face_Aspect 1.0 = 몇 % 가로
  확장)은 리그 저작 영역. 프리뷰에서 과하거나 약하면 gain(§2)이 아니라 몰프 폭으로 조정.
- **race981 range 는 시작점**: n=15 near-extremes 라 확정 분포가 아니다(원장 ①).
  코퍼스가 커지면 range 가 재중심될 수 있고, 그때 정규화 창만 갱신된다(값 산식 불변).
